# FFmpeg & Storage Gotchas

Memory, encoding, and crash-recovery rules for the conversion pipeline.

- **Memory Management**: Do NOT hold audio in RAM. Stream directly to `ChunkStore` (`_temp_work`).
- **FFmpeg Leaks**: `FFmpegService` proactively terminates and reloads itself after 10 operations. The 10-op counter is **per-instance** (the injected singleton keeps its own counter; pool workers start fresh).
- **Shared Core Blob URLs**: `FFmpegService` caches `ffmpeg-core.js`/`.wasm` Blob URLs at **module scope** (`sharedCachedCoreURL`/`sharedCachedWasmURL`), so every instance — including `AudioMerger`'s pool workers and `KokoroFallbackService`'s dedicated instance — reuses the first successful load's Blob URLs instead of re-fetching from the CDN. Only the in-memory tier failure resets these to `null` (forcing a fresh fetch from the next tier). `terminate()` does NOT clear them.
- **FFmpeg Loading**: `FFmpegService.reload` tries 3 tiers: In-memory Blob URL (shared module vars) -> IndexedDB -> Network fetch.
- **Audio Filter Chain Order**: `buildFilterChain.ts` emits (in order) `deesser → silenceremove → loudnorm → afade`. EQ and compressor are opt-in and default OFF for new users (Edge TTS speech is already clean/leveled; De-Ess stays on for harsh sibilance). Existing users keep their saved ON state via the `loadFromStorage` merge — do NOT add a settings migration. `silenceremove` runs BEFORE `loudnorm` so trimming happens at source level, not after gain changes.
- **Parallel Merge Pool**: `AudioMerger.mergeAndSave` processes merge groups on a pool of `N` `FFmpegService` instances (`N = min(mergeConcurrency, MAX_MERGE_CONCURRENCY=4)`, default 2, user-configurable via the Audio "Parallel Encoding" slider). The injected singleton is always worker[0] (keeps its lifecycle/refresh rules); extra workers come from a `ffmpegFactory` (wired in `src/services/index.ts`) and are **terminated in `finally`** after the merge. The pool only spawns `min(N, pending groups)` workers — no spurious instances for a 1-group merge. First rejection aborts `Promise.all`; in-flight workers may still complete+save (harmless: resume skips existing files). `@ffmpeg/core` is single-threaded WASM, so N>4 loses to ChunkStore I/O + cross-core contention — raise the cap via `MAX_MERGE_CONCURRENCY` only.
- **Silence Removal vs. Inter-chunk Gaps**: `FFmpegService.processAudio` inserts `silence.mp3` files between chunks (length = `silenceGapMs`) BEFORE the `-af` filter chain runs. `buildFilterChain` clamps `stop_silence` to `Math.max(silenceStopDuration, silenceGapMs/1000)` so `silenceremove` cannot eat those deliberate pauses. If you touch either the gap insertion or the `stop_silence` computation, keep them in sync or the Gap slider silently breaks above 300 ms.
- **Voice Profile Folder Name**: `ConversionOrchestrator.saveVoiceProfile` writes `<bookName>/<bookName>.json` next to the audio output. The folder and file name MUST be `sanitizeFilename(extractBookName(fileNames))` — same sanitizer `AudioMerger` uses for output folders — so the profile lands in the same folder as the audio. A raw `extractBookName` value (e.g. a 50-char slice ending in `.` or containing `:`) raises `TypeMismatchError` from `getDirectoryHandle(name, {create:true})` on NTFS. The save is **best-effort**: the `catch (err)` logs `logger.warn('Could not save voice mapping', { error })` and continues so a finished conversion is never aborted by a profile write failure.
