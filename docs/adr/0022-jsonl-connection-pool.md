A new Settings Pool tab holds one textarea: each non-blank line is one Pool entry in JSONL form (`url`, `key`, optional `name`, `model`, `temperature`, vendor extensions like `chat_template_kwargs`). `type` is accepted-and-ignored (transport is always OpenAI-compatible). When the pool is non-empty it replaces the per-stage connection triple for every LLM pass, drawn shuffled round-robin from a Fisher-Yates order frozen at Conversion start; empty means today's per-stage config behavior unchanged. The textarea persists as one raw string with per-line keys encrypted as one blob (same SecureStorage, fail-closed `Line N` errors). Draw order cycles by a Conversion-scoped atomic counter with no stickiness. A 429 parks only that entry for the provider deadline; 401/403 ejects that entry for the Conversion. Pinned per-entry `temperature` (e.g. 0.0) is used as-is on the wire even for vote passes. Per-entry `model` overrides the stage model; the Pool tab probes each entry with its resolved model. Per-entry allowlist is only `url`, `key`, `name`, `model`, `temperature`, `max_output_tokens`, `max_input_tokens`, `chat_template_kwargs`, `enable_thinking`, `reasoning_effort` plus ignored `type`; entry thinking keys skip the stage reasoning toggle outright. Pool exhaustion fails the Conversion with no mid-run fallback; exports and phase logs never carry key material; duplicate lines count as extra slots. Unknown keys (besides `type`) fail the save. Entry `max_input_tokens` below estimated prompt size only warns with the entry name and still sends (Q20 reverses the Q6 fail-early for inputs: no per-entry tokenizer in v1).

- `SettingsView` gains a `PoolTab`; pool state persists alongside `LLMSettings` with encrypted per-entry keys.
- `stages.ts` resolves credentials per request from the frozen shuffled pool order instead of the stage triple.
- `LLMApiClient` gains the allowlisted vendor-extension passthrough; `max_input_tokens` fails the Block early.
- While the pool is non-empty, `StageConfigForm` disables the per-stage `apiUrl`/`apiKey`/`model` inputs with a Pool hint; tuning fields stay editable as fallbacks.
- Pool tab is a 5th sub-tab inside `LLMTab`, not a top-level Settings tab; backup halves draw pool slots with their own retry budget; per-entry Test is advisory-only (failed entries still save, ejection happens at Conversion time).
